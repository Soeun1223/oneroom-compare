# 원룸 체크 비교

직접 보고 온 원룸 매물을 체크리스트로 점수화해서 한눈에 비교하는 웹 서비스입니다.

## 1. 목적

자취방을 구할 때 여러 집을 하루에 몰아서 보면 어느 집 물이 잘 내려갔는지, 어느 집이 전입신고가 된다고 했는지 금방 헷갈린다. 메모장이나 사진만으로는 집끼리 비교하기 어렵다.
이 서비스는 집마다 같은 3단계 체크리스트(필수 / 중요 / 있으면 좋음)를 채우게 한다. 그 결과를 필수 판정(통과·보류·탈락), 100점 만점 점수, 비용(보증금, 월세+관리비)으로 한 화면의 카드에 모아 보여 준다. 그래서 어느 집을 고를지 빠르고 덜 헷갈리게 정할 수 있다.

## 2. 사용자

- **사용자 한 유형:** 학교 근처에서 처음 자취방을 구하는 대학생 [본인 상황에 맞게 고치기]
- **줄이려는 불편:** 여러 매물을 보고 난 뒤 어떤 집이 어땠는지 기억이 섞이고, 계약 전에 꼭 확인해야 할 것(전입신고, 등기부등본 등)을 빠뜨리는 것
- **핵심 흐름:** 매물 추가(이름·보증금·월세·관리비) → 3단계 체크리스트 작성(자동 저장) → 비교 화면에서 판정·점수·비용을 보고 고르기

## 4. 사용법

1. 공개 주소에 접속한다. 체크리스트를 불러오는 동안 "체크리스트를 불러오는 중…"이 보인다.
2. **매물 추가**에서 매물 이름(예: 이문동 3층 남향), 보증금, 월세를 만원 단위로 입력한다. 관리비는 없으면 비워 둔다. 이미 매물이 있으면 이 칸은 **＋ 매물 추가** 한 줄로 접혀 있으니 눌러서 펼친다.
3. **추가하고 체크리스트 작성**을 누르면 그 매물의 체크리스트 화면으로 넘어간다.
4. **1단계 필수** 항목은 확인 완료 / 문제 있음 / 미확인 중에서 고른다. **2단계 중요**와 **3단계 있으면 좋음** 항목은 좋음 / 보통 / 나쁨 / 미확인 중에서 고른다. 고르는 즉시 저장되고 판정·점수·등급이 바로 바뀐다.
   - 휴대전화: 위쪽 바에 "통과 61점 · B"처럼 보인다. 기본 정보(이름·금액 수정, 삭제)는 접혀 있으니 눌러서 펼친다.
   - PC: 오른쪽 고정 패널에 점수 요약, 기본 정보, 위치 참고 정보가 함께 보인다.
5. (선택) **위치 참고 정보**에 동네와 학교·역까지 도보 시간을 적는다. 점수에는 들어가지 않는다.
6. **← 목록**을 눌러 **한눈에 비교**의 매물 카드를 본다. 카드마다 판정, 점수와 등급, 비용, 맨 아래 위치 참고 정보가 있다. 정렬은 판정·점수순, 월 고정비순, 보증금순, 학교 가까운 순, 최근 추가순으로 바꿀 수 있다. 카드를 누르면 그 매물의 체크리스트가 열린다.

**판정과 점수 계산 방법**

| 단계 | 항목 수 | 반영 방식 |
|---|---|---|
| 1단계 필수 (전입신고, 확정일자, 등기부 근저당·압류, 소유자 일치, 건축물대장 주거용) | 5 | 점수 없이 판정만. 하나라도 ‘문제 있음’이면 **탈락**, 미확인이 있으면 **보류**, 모두 확인 완료면 **통과** |
| 2단계 중요 (수압, 배수, 곰팡이, 채광, 난방, 소음, 보안 등) | 13 | 80점 만점 |
| 3단계 있으면 좋음 (외풍, 옵션 가전, 수납, 분리수거 등) | 9 | 20점 만점 |

- 단계 안에서는 좋음 2점, 보통 1점, 나쁨·미확인 0점에 항목 가중치(1~2)를 곱해 합산하고, 단계 배점(80·20)으로 환산한다.
- 미확인을 0점으로 둔 이유: 덜 확인한 집이 점수가 높게 나오지 않게 하려고.
- 등급: S 90점 이상, A 75점 이상, B 60점 이상, C 60점 미만.
- 비교 화면은 통과 → 보류 → 탈락 순으로 묶고, 같은 판정 안에서 점수순으로 정렬한다. 통과한 매물 중 최고 점수에 ‘추천’ 표시를 한다. 탈락 매물 카드는 점선 테두리로 구분한다.
- **위치·거리는 점수에서 뺐다.** 학교와의 거리는 사람마다 기준이 달라서 점수에 섞으면 집 자체의 상태가 가려진다. 그래서 참고 정보로만 따로 보여 준다.

## 5. 데이터 출처와 갱신일

| 데이터 | 출처 | 이용 조건 | 갱신일 |
|---|---|---|---|
| 체크리스트 항목 (`data/checklist.json`, 27개: 필수 5·중요 13·있으면 좋음 9) | [직접 정리. 참고한 자료를 적기: 예) 국토교통부·법무부 주택임대차표준계약서, 서울시 전월세 관련 안내, 자취 경험 등] | [참고 자료의 이용 조건 적기] | 2026-10-14 |
| 매물 정보·체크 결과·위치 참고 정보 | 사용자가 직접 입력 | 사용자 본인 브라우저에만 저장 | 사용자가 입력할 때마다 |

- **개인정보:** 회원가입이나 서버가 없다. 입력한 내용은 사용자의 브라우저(localStorage)에만 저장되고 어디로도 전송되지 않는다. 매물 이름, 보증금, 월세, 관리비, 그리고 선택으로 동네 이름과 도보 시간만 받는다. 입력 칸에는 "집주인 연락처 같은 개인정보는 적지 마세요"라고 안내한다. 위치는 동 이름까지만 받고, 번지·호수·도로명 번호처럼 상세 주소로 보이는 입력은 막는다.
- **외부 요청:** 글꼴(Pretendard)을 jsDelivr CDN에서 받아 온다. 이때 브라우저의 일반 접속 정보(IP 주소 등)가 CDN에 전달되지만, 사용자가 입력한 내용은 전달되지 않는다. 글꼴을 못 받으면 기기 기본 글꼴로 보인다.
- **인증키:** 외부 API를 쓰지 않아 인증키가 없다. 나중에 공공 API를 붙이면 키는 GitHub Secrets에만 둔다.

## 7. 알려진 한계

- 기록이 이 브라우저에만 남는다. 휴대전화에서 체크한 내용을 PC로 옮기거나 다른 사람과 공유할 수 없다. 기기 간 동기화나 공유 링크는 다음 단계 계획이다.
- 브라우저의 사이트 데이터를 지우면 기록도 함께 지워진다.
- 시크릿 모드처럼 저장이 막힌 환경에서는 경고를 띄우지만, 창을 닫으면 입력이 사라진다.
- 체크리스트 항목과 단계(필수·중요·있으면 좋음), 가중치는 내가 정한 기준이라 사람마다 중요도가 다를 수 있다. 사용자가 항목을 다른 단계로 옮기는 기능은 아직 없다.
- 도보 시간은 사용자가 직접 재서 적는 값이라 정확하지 않을 수 있고, 지도와 연동되지 않는다.
- 실제 시세(실거래가)와 비교하지 않는다. 비싼지 싼지는 사용자가 판단해야 한다.
- 사진은 첨부할 수 없다.
